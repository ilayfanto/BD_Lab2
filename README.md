# ЛР2 — ИИ для обнаружения DDoS-атак (PostgreSQL + Python)

Продолжение ЛР1: тот же функционал (создание схемы, ввод данных, вывод, ограничения, ссылочная целостность, лог) плюс средства ALTER TABLE, расширенный SELECT, текстовый поиск, строковые функции и мастер JOIN.

## Стек
- Python 3.12+ (проверено на 3.15), PySide6, psycopg2
- PostgreSQL 13+ (проверено на 19)
- ОС: Windows / Linux / macOS

## Запуск
```
python -m venv .venv
.venv\Scripts\activate          # Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
python app.py
```
Подключение задаётся в `config.ini`: localhost:5432, БД `ddos_lab2`, postgres/postgres. Если базы нет, она создаётся при подключении. Порядок работы: «Подключиться» → «Создать схему и таблицы» → «Добавить демо-данные».

## Что добавлено в ЛР2
1. **ALTER TABLE** — кнопка «Изменить структуру» в главном окне. Операции: добавить или удалить столбец; переименовать столбец или таблицу; изменить тип (с `USING`); задать или убрать NOT NULL и DEFAULT; добавить CHECK, UNIQUE, FOREIGN KEY (с ON DELETE / ON UPDATE); удалить ограничение (с CASCADE). Перед выполнением показывается SQL. Каждое изменение идёт в транзакции и при ошибке откатывается через ROLLBACK. Справа видна текущая структура таблицы: столбцы и ограничения.
2. **Конструктор SELECT** — вкладка окна «Показать данные». Выбор столбцов, агрегатные функции (COUNT, SUM, AVG, MIN, MAX), WHERE (с объединением условий через AND/OR), GROUP BY, HAVING, ORDER BY, LIMIT, без ручного написания SQL.
3. **Поиск по тексту** — тип поиска выбирается в выпадающем списке: `LIKE`, `ILIKE`, `NOT LIKE`, `~`, `~*`, `!~`, `!~*`, `SIMILAR TO`. Для каждого есть подсказка с примером.
4. **Строковые функции** — отдельная кнопка в окне вывода данных. Функции: UPPER, LOWER, INITCAP, LENGTH, TRIM/LTRIM/RTRIM, SUBSTRING (по позиции и по регулярке), POSITION, REPLACE, LPAD/RPAD, CONCAT и `||`. Применяются к столбцу таблицы или к своей строке. Результат показан рядом с исходным значением, вместе с длиной до и после; границы строк «…» помогают увидеть пробелы. Кнопка «Все функции сразу» применяет все функции к одному значению.
5. **Мастер JOIN** — основная таблица и цепочка соединений: тип (INNER, LEFT, RIGHT, FULL, CROSS), таблица, поля связи. Поля связи подставляются по внешним ключам. Результат можно сортировать щелчком по заголовку и фильтровать.

Все новые окна читают структуру БД из системного каталога (`pg_attribute`, `pg_constraint`), поэтому продолжают работать после ALTER TABLE. Формы и сводная таблица из ЛР1 рассчитаны на исходную схему. Если, например, переименовать таблицу, они сообщат об ошибке. Исходная структура восстанавливается кнопкой «Создать схему и таблицы».

## Структура БД (схема `ddos_ai`)
| Таблица | Назначение | Ключи и ограничения |
|---|---|---|
| `models` | модели ИИ | PK, UNIQUE(name), CHECK, ENUM `model_family`, `tags text[]` |
| `datasets` | датасеты трафика | PK, UNIQUE(name), CHECK, `attack_types attack_type[]` |
| `experiments` | эксперименты | FK → models (RESTRICT / CASCADE), FK → datasets (SET NULL), UNIQUE(title, model_id) |
| `runs` | запуски | FK → experiments (CASCADE), UNIQUE(experiment_id, run_no), CHECK метрик 0..1 |

В демо-данных есть модель без экспериментов, датасет без экспериментов и эксперимент без датасета и без запусков. На них видна разница между типами JOIN.

## Логирование
`app.log`: INFO/ERROR с временными метками — подключения, DDL (включая ALTER TABLE), DML, SELECT из конструктора, COMMIT/ROLLBACK, ошибки.

## Файлы
- `app.py` — главное окно, формы ввода, окно вывода данных
- `lab2.py` — окна ЛР2: ALTER TABLE, конструктор SELECT, поиск, мастер JOIN, строковые функции
- `builders.py` — безопасная сборка SQL (`psycopg2.sql`, экранирование имён и значений)
- `db.py` — подключение, транзакции, чтение структуры БД, понятные сообщения об ошибках, лог
- `schema.sql` — DDL-скрипт
- `config.ini` — параметры подключения
